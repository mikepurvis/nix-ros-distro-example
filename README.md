# nix-ros-distro-example

A repo that keeps its own generated ROS package expressions and builds them
with [nix-ros-overlay][overlay]'s machinery, without forking it. It pairs with
branch [`mkrosdistro-AN2ATG0`][branch] of the overlay; see
`docs/external-distros.md` there for the user-facing API.

[overlay]: https://github.com/lopsided98/nix-ros-overlay
[branch]: https://github.com/mikepurvis/nix-ros-overlay/tree/mkrosdistro-AN2ATG0

## What's here

Two distros, both generated by the overlay's `update-overlay` (superflore)
into this repo and built with the overlay's machinery.

### banana: a few packages over the bundled jazzy

`distros/banana/{angles,ackermann-msgs,example-interfaces}`, generated from
the jazzy in the rosdistro the overlay pins:

```sh
nix run .#update-banana -- angles ackermann_msgs example_interfaces
```

superflore always writes under `distros/<ros distro>` and commits to the
repo it is given, so `update-banana` runs it in a scratch repo and copies the
expressions into `distros/banana`. Commit the result yourself.

`rosPackages.banana` is the bundled jazzy with these laid over it, so anything
not generated here falls through to jazzy. Its drvPaths equal
`rosPackages.jazzy`'s, so it shares the overlay's binary cache.

```sh
nix build .#env              # the three packages in a ros-env
nix build .#banana.angles
```

### mango: a distro of its own, from a rolling snapshot

`rosdistro/` is a private rosdistro index with one distro, mango.
`rosdistro/mango/distribution.yaml` is rolling's distribution file at the
rosdistro commit the overlay pins (2026-09-18). `update-mango` is
`update-overlay` pointed at a copy of the pinned rosdistro tree with that
index laid over it, so rosdep comes along unchanged.

`distros/mango` is ros_base and everything it depends on, test dependencies
included (generated expressions name them as `checkInputs`), 230 packages:

```sh
nix run .#update-mango -- --dry-run --no-branch --output-repository-path . \
  --tar-archive-dir .tar --ros-distro mango --only ros_base ...
```

The first run builds a package.xml cache for the index (~1600 fetches,
network-bound) under `~/.cache/rosdistro-cache`. Package names are
`ros-mango-*` and `ROS_DISTRO` is `mango`. Nothing falls through to a bundled
distro, but `overridesFrom = "rolling"` still applies rolling's fixups, which
carry the vendor package hashes for these versions.

```sh
nix build .#mango-ros-base
```

Nothing in mango is in any binary cache, so that builds the whole core.

To move mango to a newer snapshot, copy a newer `rolling/distribution.yaml`
over `rosdistro/mango/distribution.yaml` and rerun `update-mango`. Its cache is
keyed on the file contents. Versions that run ahead of the overlay's rolling
fixups may need overrides of their own.

## What is coupled today (upstream develop / dev-out)

1. `distros/distro-overlay.nix` imports `./${distro}/generated.nix` and
   `./${distro}/overrides.nix` by relative path. `distro` is the only input.
2. `distro` is used for six things at once: those two paths, the
   `rosPackages.${distro}` attribute that splicing looks up for
   cross-compilation, `ROS_DISTRO` passed to `buildRosPackage`, the Qt 5/6
   choice, and the jazzy-only dev-output split. A distro named anything other
   than an upstream one gets none of the fixups, and a second copy of jazzy
   under another name splices against the wrong set.
3. `rosPackages.mkRosDistroOverlay` exists but takes `{ version, distro }`
   only and has to be called as `mkRosDistroOverlay args self super`.
4. The bundled fixups (`overrides`, `ros2-overlay.nix`, `qt*-overlay.nix`,
   `<distro>/overrides.nix`) reference `rosSuper.<pkg>` for hundreds of
   packages. Applied to a smaller set they leave attributes that throw when
   evaluated, which breaks anything that walks the scope.
5. The generator is less coupled than it looks. superflore writes under
   `distros/<distro>/` in any git repo given by `--output-repository-path`, and
   takes its index from `ROSDISTRO_INDEX_URL`. The gaps: `--only` writes no
   `generated.nix`; `update-overlay` is a flake-only output and its
   `rosdistro` argument must carry `rev`/`lastModifiedDate`; pnames are always
   `ros-<distro>-<pkg>`.

## What the branch changes

- `distro-overlay.nix` takes `{ distro, version, name ? distro, generated ?
  bundled, overridesFrom ? distro, upstreamOverrides ? true, overrides ? [ ],
  qtVersion ? by overridesFrom }`. `name` is only the attribute and splice
  key, and `distro` sets `ROS_DISTRO`. `overridesFrom` names the bundled
  distro whose `overrides.nix` and Qt version apply, so mango, a renamed
  rolling snapshot, still gets rolling's fixups.
  `generated` takes an overlay, a file, a directory of `<pkg>/default.nix`
  (so superflore's `--only` output needs no `generated.nix`), or a list.
- Against a set that isn't the bundled one, bundled fixups are filtered to
  packages that exist, plus additions no bundled distro defines (aliases and
  packages taken from nixpkgs). This uses only attribute names, so it
  doesn't force any package.
- `rosPackages.mkRosDistro args` returns the scope; the bundled distros use it.
  `mkRosDistroOverlay` is kept for compatibility.
- `lib/distro-overlays.nix` (flake output `lib`) has pkgs-free nixpkgs
  overlays: `rosDistroOverlay`, `extendRosDistro`, and `bundledGenerated` and
  `generatedOverlay` helpers. It is a plain file, so non-flake users import it
  directly.
- All bundled distros evaluate to the same drvPaths as before (checked on
  jazzy, humble, kilted, lyrical and rolling, including `desktop`).
- [`mkrosdistro-develop-AN2ATG0`][develop] carries the same change on
  upstream develop, independent of dev-out.

[develop]: https://github.com/mikepurvis/nix-ros-overlay/tree/mkrosdistro-develop-AN2ATG0

## Design notes and open questions

- The `distro-overlay.nix` argument split and `mkRosDistro` are additive and
  change no hashes for the bundled distros. They also make the existing
  `mkRosDistroOverlay` easier to call: it takes the arguments alone, rather
  than the arguments followed by `self super`.
- `lib/distro-overlays.nix` is a plain file that doesn't need `pkgs`, so it
  works without flakes. The flake's `lib` output re-exports it.
- Pruning fixups for packages a set doesn't have is the least obvious part.
  The alternative is `upstreamOverrides = false` and leaving the fixups to
  the consumer, which is simpler but means repeating vendor hashes and
  similar fixes. The bundled jazzy carries one such fixup of its own,
  `gazebo-ros`, which only exists in ROS 1. That is the class of problem in
  #812.
- superflore needs no changes: it already writes to any git repo and reads
  any rosdistro index, and `generated` accepts the directory that `--only`
  leaves behind. `update-overlay` is only reachable through the flake. A
  non-flake entry point, with `rosdistro` defaulting to the commit in
  `flake.lock`, could follow if anyone needs one.
